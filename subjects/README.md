# 科目プロファイル（サンプル）

ここに置いてあるのは**サンプル**である。自分の科目のプロファイルは、これを
コピーして育てるところから始められる。

| ファイル | 想定する科目 |
|---|---|
| `cs_lang_c_intro.yaml` | プログラミング入門（C 言語）。テスト実行による正誤判定が主 |
| `cs_network_python.yaml` | ネットワークプログラミング（Python） |
| `report_ja.yaml` | 実験レポート（PDF 提出）。内容は AI とルーブリックで判定 |

**コメントを消さずに読むこと。** 各ファイルの行数の大半はコメントで、そこには
「なぜその値なのか」（実測値・過去に起きた事故・関連する ADR）が書いてある。
値だけを写すと、次に誰かがその値を変えるときに理由を失う。

## 採点の宣言であって、コードではない

科目の違いはコードではなくこの宣言で表す（ADR 0002）。どの評価器をどの順で
走らせるか、確信度がいくつを下回ったら人が見るか、といった採点の設定である。
評価器そのものは Python のパッケージ（`evaluators/*`）で、entry point から
発見される ── **存在しない名前を書けばロード時に落ちる**（採点時ではない）。

## 運用では git の外に置く

`AIJUDGE_PROFILES_DIR` で置き場所を指定する（`docs/RUNNING.md` の環境変数表）。
**運用のプロファイルをこのディレクトリに置かないこと** ── デプロイは
`git checkout <tag>` でコードを入れ替えるので、ここに置いた運用の変更は
そのとき消える。

```fish
# 初回だけ、サンプルを運用の置き場所へコピーして種にする
sudo -u aijudge mkdir -p /srv/aijudge/subjects
sudo -u aijudge cp /opt/aijudge/subjects/*.yaml /srv/aijudge/subjects/
```

`web` / `review` / `worker` / `admin` の**すべてが同じ場所を指すこと**。
ワーカーだけ古い宣言を読むと、画面で見えている設定と実際の採点が食い違う。
