# 科目プロファイル（サンプル）

ここに置いてあるのは**サンプル**である。自分の科目のプロファイルは、サンプルを
コピーし、科目に合わせて書き換えて作ればよい。

| ファイル | 想定する科目 |
|---|---|
| `cs_lang_c_intro.yaml` | プログラミング入門（C 言語）。テスト実行による正誤判定が主 |
| `cs_network_python.yaml` | ネットワークプログラミング（Python） |
| `report_ja.yaml` | 実験レポート（PDF 提出）。内容は AI とルーブリックで判定 |
| `cs_sandbox_kc.yaml` | 習熟度を確かめるための試験用の科目（砂場・#328）。`cs_lang_c_intro` のコピーで、**違うのは名前だけ** |

`cs_sandbox_kc` の名前を変えてあることには意味がある。観測レコードは科目プロファイル
ごとのディレクトリに蓄積され、`aijudge-eval --subject <名前>` はそのうち 1 つしか
読まない。そのため、この名前で採点した提出は、本番の科目の精度・一致度の標本に 1 件も
入らない。砂場のコース定義は `sandbox/course.yaml`（`docs/RUNNING.md` の
「習熟度を確かめる砂場」）。

**コメントを消さずに読むこと。** 各ファイルの行の大半はコメントで、そこには
「なぜその値なのか」（実測値・過去に起きた事故・関連する ADR）が書いてある。
値だけをコピーすると、次に誰かがその値を変えるときに、理由が分からなくなる。

## 採点の宣言であって、コードではない

科目の違いは、コードではなくこの宣言で表す（ADR 0002）。プロファイルに書くのは、どの評価器をどの順で
実行するか、確信度がいくつを下回ったら人が確認するか、といった採点の設定である。
評価器そのものは Python のパッケージ（`evaluators/*`）で、entry point から
読み込まれる。**存在しない評価器の名前を書くと、採点時ではなく読み込み時にエラーになる。**

## 運用では git の外に置く

`AIJUDGE_PROFILES_DIR` で置き場所を指定する（`docs/RUNNING.md` の環境変数表）。
**運用のプロファイルを、このディレクトリに置かないこと。** デプロイは
`git checkout <tag>` でコードを入れ替えるので、ここで運用のために変更した内容は、
デプロイのたびに消える。

```fish
# 初回だけ、サンプルを運用の置き場所へコピーして種にする
sudo -u aijudge mkdir -p /srv/aijudge/subjects
sudo -u aijudge cp /opt/aijudge/subjects/*.yaml /srv/aijudge/subjects/
```

`web` / `review` / `worker` / `admin` の**すべてに、同じ場所を指定すること**。
ワーカーだけが古い宣言を読むと、画面に表示される設定と実際の採点が食い違う。
