# レポート採点の測定（ネットワーク及び演習・2025 年度）

教員が実際に付けた成績（19 件）に対して、AI 採点がどれだけ一致するかを測る。
**採点そのものは `GradingPipeline` にやらせる。** ここに別の採点を書くと、
測ったものが本番の採点と違うものになる。

## 使い方

提出物と教員の採点表は**この repository に置かない**（学籍番号と、個々の
学生への教員のコメントが入っている）。設計検討ディレクトリの

    network-report2025/          提出物 19 件（PDF / DOCX）
    network2025-report.csv       教員の採点（観点別）

を読む。`extract.py` が本文を起こして `index.json` と `bodies/` を作り、
以降の反復はそれを読むので PDF を開き直さない。

```fish
uv run python evals/report_ja/extract.py                  # 下ごしらえ
uv run python evals/report_ja/grade.py --name final --samples 3 --workers 5
uv run python evals/report_ja/measure.py --name final
```

`grade.py` の出力（`runs/*.json`）も学生の提出内容に触れるので置かない。

## ルーブリック

`rubric.py` は**教員が実際に使った採点表をそのまま写したもの**である。

| 観点 | 配点 | 段階 | 担当 |
|---|---:|---|---|
| 体裁 | 4 | 0–4 | `report_structure`（決定的） |
| 実験先 | 3 | 0–3 | `rubric_ai_judge` |
| 実験条件 | 2 | 0–2 | `rubric_ai_judge` |
| 独自性 | 8 | 0–8 | `rubric_ai_judge` |
| 考察 | 4 | 0–4 | `rubric_ai_judge` |
| 結果の提示 | 2 | 0–2 | `rubric_ai_judge` |

**段階は教員の配点と 1 対 1 にしてある。** 丸めた段階に写すと、写した時点で
一致度が変わり、何を測ったのか分からなくなる。

以前の 4 観点（体裁・設計・結果・考察、重み 0.2/0.25/0.2/0.35）は設計時に
作った仮のもので、教員の採点表とは観点の数も配点も違っていた。**違うものを
測っても一致度は測れない。**

## 測定結果（2026-08-28、`gemma4:e4b`、samples=3）

| 観点 | 完全一致 | κ | QWK |
|---|---:|---:|---:|
| 体裁 | 57.9% | +0.200 | +0.406 |
| **実験先** | **89.5%** | **+0.790** | **+0.835** |
| 実験条件 | 78.9% | +0.406 | +0.406 |
| 独自性 | 21.1% | +0.095 | +0.454 |
| 考察 | 26.3% | −0.064 | +0.127 |
| 結果の提示 | 68.4% | +0.174 | +0.174 |

合計点（23 点尺度）**r = +0.802 / QWK = +0.599**、平均絶対差 2.79 点、
レビュー行き **11%**（基準 30% 以下）、19 件すべてで全観点が採点できた。

§9.2 Phase 3 の基準は QWK ≥ 0.60。**合計ではほぼ届き、観点別では実験先しか
届いていない。**

## 分かったこと

- **サンプル数 2 では確信度が 2 値にしかならない。** 自己一貫性から確信度を
  作る以上、2 本では 1.0 か 0.5 しか出ず、閾値をどこに置いても
  「1 つでも割れたら人間」になる。実測でレビュー行き 58%。3 本にすると
  2 対 1 の多数決が表現でき、11% に落ちた（`confidence_below: 0.6`）。
  **これは科目ではなく評価器の性質なので、他の科目にも効く。**
- **大きいモデルが良いとは限らない。** `qwen3.8:27b-mlx` で測り直したところ
  全体に辛くなり（平均 −2.71 点、教員が満点を付けた 3 件で −7〜−10 点）、
  合計 QWK は 0.625 → 0.289 に落ちた。JSON も崩れやすい
  （``` で囲む・制御文字）。既定の `gemma4:e4b` の方が良い。
- **独自性は数え上げにすると外れる。** 「軸の本数」「指標の種類」で段階を
  定義し直したら平均 2.26 点辛くなり QWK が 0.570 → 0.234 に落ちた。教員が
  見ているのは数え上げではなく踏み出した度合いで、曖昧なままの方が一致する。
- **結果の提示は本文からは判定できない。** 教員が 1 点にした 7 件と 2 点に
  した 11 件を分けているのはグラフの有無・質だが、グラフは画像なので
  正規化で落ちる。図表番号の出現数でも分かれない（実測）。**この観点は
  ページ画像を見るか、人間が持つしかない。**
- **体裁も教員の判断とは別物。** 決定的な 3〜4 本の条件（節・分量・数値・
  提出形式）は、教員が見ている体裁（図表の作り・ページ番号・見栄え）を
  代理していない（κ = 0.20）。
- **弱いレポートを甘く見る。** 教員が 7〜11 点を付けた 4 件がすべて 15 点に
  なった。最大の誤差源で、しかも危険な向き（弱いレポートが及第に見える）。

## 注意

n = 19 で、4 回の反復はいずれも同じ 19 件に対する当てはめである。
`evals/gates.yaml` の `min_sample_size: 30` を下回るので、**この数字は
ゲートの判定には使えない**（`NOT_MEASURED`）。方向を見るためのものである。
