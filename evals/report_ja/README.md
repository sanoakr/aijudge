# レポート採点の測定（ネットワーク及び演習・2025 年度）

教員が実際に付けた成績（19 件）に対して、AI 採点がどれだけ一致するかを測る。
**採点そのものは `GradingPipeline` にやらせる。** ここに別の採点を書くと、
測ったものが本番の採点と違うものになる。

## 使い方

提出物と教員の採点表は**この repository に置かない**（学籍番号と、個々の
学生への教員のコメントが入っている）。設計検討ディレクトリの

    network-report2025/          提出物 19 件（PDF / DOCX）
    network2025-report.csv       教員の採点（観点別）

を読む。`extract.py` が本文を起こして `index.json` と `bodies/` を作り、
以降の反復はそれを読むので PDF を開き直さない。

```fish
uv run python evals/report_ja/extract.py                  # 下ごしらえ
uv run python evals/report_ja/grade.py --name final --samples 3 --workers 5
uv run python evals/report_ja/measure.py --name final
```

`grade.py` の出力（`runs/*.json`）も学生の提出内容に触れるので置かない。

## ルーブリック

`rubric.py` は**教員が実際に使った採点表をそのまま写したもの**である。

| 観点 | 配点 | 段階 | 担当 |
|---|---:|---|---|
| 体裁 | 4 | 0–4 | `report_structure`（決定的） |
| 実験先 | 3 | 0–3 | `rubric_ai_judge` |
| 実験条件 | 2 | 0–2 | `rubric_ai_judge` |
| 独自性 | 8 | 0–8 | `rubric_ai_judge` |
| 考察 | 4 | 0–4 | `rubric_ai_judge` |
| 結果の提示 | 2 | 0–2 | `rubric_ai_judge` |

**段階は教員の配点と 1 対 1 にしてある。** 丸めた段階に写すと、写した時点で
一致度が変わり、何を測ったのか分からなくなる。

以前の 4 観点（体裁・設計・結果・考察、重み 0.2/0.25/0.2/0.35）は設計時に
作った仮のもので、教員の採点表とは観点の数も配点も違っていた。**違うものを
測っても一致度は測れない。**

## 測定結果（2026-08-28、`gemma4:e4b`、samples=3）

| 観点 | 完全一致 | κ | QWK |
|---|---:|---:|---:|
| 体裁 | 57.9% | +0.200 | +0.406 |
| **実験先** | **89.5%** | **+0.790** | **+0.835** |
| 実験条件 | 78.9% | +0.406 | +0.406 |
| 独自性 | 21.1% | +0.095 | +0.454 |
| 考察 | 26.3% | −0.064 | +0.127 |
| 結果の提示 | 68.4% | +0.174 | +0.174 |

合計点（23 点尺度）**r = +0.802 / QWK = +0.599**、平均絶対差 2.79 点、
レビュー行き **11%**（基準 30% 以下）、19 件すべてで全観点が採点できた。

§9.2 Phase 3 の基準は QWK ≥ 0.60。**合計ではほぼ届き、観点別では実験先しか
届いていない。**

## 分かったこと

- **サンプル数 2 では確信度が 2 値にしかならない。** 自己一貫性から確信度を
  作る以上、2 本では 1.0 か 0.5 しか出ず、閾値をどこに置いても
  「1 つでも割れたら人間」になる。実測でレビュー行き 58%。3 本にすると
  2 対 1 の多数決が表現でき、11% に落ちた（`confidence_below: 0.6`）。
  **これは科目ではなく評価器の性質なので、他の科目にも効く。**
- **大きいモデルが良いとは限らない。** `qwen3.8:27b-mlx` で測り直したところ
  全体に辛くなり（平均 −2.71 点、教員が満点を付けた 3 件で −7〜−10 点）、
  合計 QWK は 0.625 → 0.289 に落ちた。JSON も崩れやすい
  （``` で囲む・制御文字）。既定の `gemma4:e4b` の方が良い。
- **独自性は数え上げにすると外れる。** 「軸の本数」「指標の種類」で段階を
  定義し直したら平均 2.26 点辛くなり QWK が 0.570 → 0.234 に落ちた。教員が
  見ているのは数え上げではなく踏み出した度合いで、曖昧なままの方が一致する。
- **結果の提示は本文からは判定できない。** 教員が 1 点にした 7 件と 2 点に
  した 11 件を分けているのはグラフの有無・質だが、グラフは画像なので
  正規化で落ちる。図表番号の出現数でも分かれない（実測）。**この観点は
  ページ画像を見るか、人間が持つしかない。**
- **体裁も教員の判断とは別物。** 決定的な 3〜4 本の条件（節・分量・数値・
  提出形式）は、教員が見ている体裁（図表の作り・ページ番号・見栄え）を
  代理していない（κ = 0.20）。
- **弱いレポートを甘く見る。** 教員が 7〜11 点を付けた 4 件がすべて 15 点に
  なった。最大の誤差源で、しかも危険な向き（弱いレポートが及第に見える）。

## 注意

n = 19 で、4 回の反復はいずれも同じ 19 件に対する当てはめである。
`evals/gates.yaml` の `min_sample_size: 30` を下回るので、**この数字は
ゲートの判定には使えない**（`NOT_MEASURED`）。方向を見るためのものである。

## 3 者の相互一致度（`agreement.py`）

**CSV の採点も LLM が付けたものである。** したがって上の表は「正解に対する
精度」ではなく、**独立した採点者どうしの一致度**である。3 者で測ると別の絵が
出る（samples=2・同じルーブリックで揃えた 2 本と CSV）。

合計点（23 点尺度）:

| | n | 平均 | σ | 範囲 |
|---|--:|--:|--:|--:|
| CSV | 19 | 15.42 | **5.13** | **7–23** |
| gemma4:e4b | 18 | 16.22 | 2.68 | 11–21 |
| qwen3.8:27b | 17 | 13.41 | 1.82 | 10–17 |

| 組 | n | r | QWK | 平均差 | 平均絶対差 |
|---|--:|--:|--:|--:|--:|
| CSV ↔ gemma4 | 18 | +0.789 | +0.625 | +0.83 | 2.83 |
| CSV ↔ qwen3.8 | 17 | +0.562 | +0.289 | −2.71 | 4.12 |
| gemma4 ↔ qwen3.8 | 16 | **+0.791** | **+0.354** | −3.31 | 3.31 |

**順位は合っていて、尺度が合っていない。** gemma と qwen は r = 0.791 で
ほぼ同じ順に並べるのに QWK は 0.354 しかない ── 平均が 3.31 点ずれ、
どちらも CSV より狭い範囲に詰まっているためである。**相関と QWK を並べて
見ないと、「違う順に並べている」のか「同じ順に狭く並べている」のかが
分からない。**

これは**モデルの質の問題ではなく較正の問題**である。段階の記述だけでは
「どこからが 8 点か」が決まらず、採点者ごとに原点と幅が違う。効くのは
より大きいモデルではなく、**段階ごとの実例（アンカー）をルーブリックに
添えること**である。

観点別で目立つもの:

- **体裁は 2 本が κ = 1.000 で完全一致するが、これは一致ではない。**
  `report_structure` が決定的に判定しており、LLM は関与していない。
  同じコードが同じ入力に同じ答えを返しただけである。CSV とは
  κ = 0.200 で、**CSV の採点者は本文から読めないもの（図表の作り・
  ページの見栄え）を見ている**ことを示す
- **考察では、2 つのモデルどうし（κ +0.205 / QWK +0.399）が
  CSV との一致（κ ≈ 0 / QWK +0.126・−0.067）を上回る。** 独自性でも
  同じ向き。ローカルの 2 つは互いに似た読み方をしており、CSV の採点者は
  そのどちらとも違う読み方をしている
- **結果の提示は gemma が 19 件すべてに 2 点を付けた（σ = 0）。**
  分散が無いので κ は定義上 0 になる。判定できていない

同じモデル・同じサンプル数で**ルーブリックの記述だけを変えた 2 本**は
QWK = 0.647 で一致する ── **どちらが CSV と一致する度合い（0.599 / 0.584）
より高い。** 記述の違いより採点者の違いの方が大きい。

```fish
uv run python evals/report_ja/agreement.py
uv run python evals/report_ja/agreement.py --raters csv "final:gemma4(s=3)"
```

## Sonnet 5 / Opus 5 を足した 5 者比較（2026-08-28）

API の資格情報が無いので、**サブエージェント経由**で同じ文面を判定させた
（`build_prompts.py` → `agent_out/` → `collect_agent_runs.py`）。
文面と段階の記述は `rubric.py` から組むので同じだが、**同条件ではない**。

| | gemma4 / qwen3.8 | Sonnet 5 / Opus 5 |
|---|---|---|
| 経路 | `rubric_ai_judge` + ゲートウェイ | サブエージェント 1 回 |
| 観点 | 1 観点ごとに 1 回 | 6 観点まとめて 1 回 |
| 自己一貫性 | 3 本（gemma4）/ 2 本（qwen3.8） | 1 本（確信度なし・振り分けなし） |
| 制約デコード | JSON スキーマあり | なし |
| 本文 | 原文 | **氏名・学籍番号を伏せたもの** |

**本文が氏名を含むので、学外のモデルには匿名化してから渡した**（P7。
`anonymize.py`、19 件で 11 箇所）。`gemma4` / `qwen3.8` は原文を見ている。

### 合計点（23 点尺度）

| 採点者 | n | 平均 | σ | 範囲 |
|---|--:|--:|--:|--:|
| CSV | 19 | 15.42 | **5.13** | **7–23** |
| gemma4:e4b | 19 | 16.42 | 2.41 | 11–20 |
| qwen3.8:27b | 17 | 13.41 | 1.82 | 10–17 |
| Sonnet 5 | 19 | 14.32 | 2.70 | 8–19 |
| Opus 5 | 19 | 13.95 | 2.54 | 10–18 |

| 組 | r | QWK | 平均差 |
|---|--:|--:|--:|
| CSV ↔ gemma4 | +0.802 | **+0.599** | +1.00 |
| CSV ↔ Sonnet 5 | +0.645 | +0.512 | −1.11 |
| CSV ↔ Opus 5 | +0.578 | +0.431 | −1.47 |
| CSV ↔ qwen3.8 | +0.562 | +0.289 | −2.71 |
| **Sonnet 5 ↔ Opus 5** | +0.716 | **+0.708** | −0.37 |
| qwen3.8 ↔ Opus 5 | +0.760 | +0.676 | +0.82 |
| gemma4 ↔ Opus 5 | +0.621 | +0.414 | −2.47 |
| gemma4 ↔ Sonnet 5 | +0.538 | +0.399 | −2.11 |
| gemma4 ↔ qwen3.8 | +0.697 | +0.304 | −3.29 |

### 分かったこと

**上位モデルほど CSV に近い、ということは無い。** CSV との一致は
gemma4 (0.599) > Sonnet 5 (0.512) > Opus 5 (0.431) > qwen3.8 (0.289) で、
**モデルの一般的な能力の順ではない。** 「良いモデルを使えば教員に近づく」は
この課題では成り立たない。

**モデルどうしの方がよく一致する。** Sonnet 5 ↔ Opus 5 は QWK 0.708 で、
どちらが CSV と一致する度合いよりも高い。観点別ではさらに極端で、
**考察は κ = 0.915 / QWK = 0.964**（CSV とはどちらも ≈ 0）、
実験先は κ = 0.902。**5 つの採点者の中で最もよく揃う 2 つは、この 2 つである。**

つまり食い違いは「どのモデルが賢いか」ではなく**採点者が何を見ているか**の
差である。ローカル 2 つ、Claude 2 つ、CSV の 3 つの塊に分かれる。

**CSV の採点者だけが尺度を使い切っている**（σ 5.13、7–23）。他の 4 つは
σ 1.8–2.7 に詰まる。全員が同じ向きに詰まるので、これはモデル固有の癖ではなく
**アンカーの無いルーブリックの性質**である。

**結果の提示で Sonnet 5 と Opus 5 は σ 0.65 / 0.68 のばらつきを出した**
（gemma4 は σ 0.22 でほぼ全員に 2 点）。CSV との κ も Sonnet 5 が 0.317 で
最も高い。ただし QWK は 0.285 に留まり、**グラフが見えない**という
限界そのものは変わっていない。

**構造化出力の失敗は上位モデルでも起きる。** Sonnet 5 が 1 件で JSON の
区切りに全角カンマ（`，`）を書き、パースできなかった。qwen3.8 の
``` 囲み・制御文字と同じ種類の失敗である。ゲートウェイは再試行するので、
ここでも 1 回やり直した（やり直して通った）。**制約デコードの無い経路を
本番に使ってはならない**ことの実例。

### 同じモデルを 2 回走らせてしまった（偶然の再現性の測定）

Y230058 は JSON の壊れで走らせ直したが、**最初のエージェントも遅れて自分で
書き直していた**ため、同じモデル・同じ文面の判定が 2 つ手に入った。

|  | 体裁 | 実験先 | 条件 | 独自性 | 考察 | 結果 | 合計 |
|---|--:|--:|--:|--:|--:|--:|--:|
| 1 回目 | 2 | 1 | 2 | 4 | 3 | 0 | 12 |
| 2 回目 | 2 | 1 | 2 | 5 | 2 | 0 | 12 |

**6 観点のうち 2 つで割れ、合計は偶然一致した。** これは
`samples=1` では測れないばらつきそのもので、上の観点別の数字が
**この程度は動きうる**ことを意味する（実際、採り直しで考察の
Sonnet 5 ↔ Opus 5 は κ 0.835 → 0.915 に動いた）。合計を使った数字は
1 件では動かなかったが、それは偶然である。

**サンプル 1 本の観点別 κ を、差の根拠にしてはならない。**

### 注意

- **同条件ではない**（上の表）。観点をまとめたこと・サンプル 1 本・匿名化の
  3 つが効きうる。特に**まとめて 1 回**は設計方針 §04 step 3 が禁じた形で、
  観点間の引きずりが入る。Sonnet 5 ↔ Opus 5 の高い一致には、この構成が
  共通していることも寄与しうる
- n = 19。`min_sample_size: 30` 未満で、ゲート判定には使えない
