# 段階 4 の地図: `manage.py` をどう分けるか

段階的な立て直し（`staged-refactor.md`）の段階 4 の下準備。**2026-09-27、v1.36.33 の main で測った。**
移す前に、補助関数がどの画面の領域から使われているか、テストがどこで薄いかを機械で
数え、分け方の根拠にする。数字は AST で数えたもので、手で数えたものではない
（測り方は末尾）。

## 分け方の基準

行数よりも、**ファイル構造の妥当性**（画面の領域・責務で分け、どこに何があるか
迷わない）、**メンテナンス性**（一緒に直すものを一緒に置く・共有の補助は 1 か所）、
**テストしやすさ**（ルートの関数から業務の判断を切り離し、補助を単体で試せる）を
優先する。1 ファイル 1,000 行以内は目安（2026-09-27 にユーザーと決めた）。

## 分け方の案

`manage.py` を `manage/` パッケージにする。`manage/__init__.py` の `register()` が各モジュールの
`register(router, templates)` を呼ぶ（ルートの順は写しのテストが見る）。

| モジュール | 中身 | 見込み | なぜこの境界か |
|---|---|---|---|
| `messages.py` | 保存後の文言（`SAVED_MESSAGES`）と画面の段の定数 | 150 前後 | 文言は全画面が引き、テンプレートの鍵と対になる。1 か所で読める |
| `common.py` | 主体とコースの解決、権限の読み替えの薄い包み、フォームの読み取り（日時・分・キー） | 300 前後 | どの画面も最初にすること。単体で試せる |

見込みは「ルート＋専用の補助」に、共有の補助を振ったもの。4-1 で補助を外に出したあと測り直す。

## 4-1 の見通し（`register()` の中の補助を外に出す）

25 個のうち、`register()` の変数を掴むのは **`templates` を使う 4 つだけ**（`_course_page`・
`_task_page`・`_render_groups`・`_kc_page`）。残る 21 個は何も掴まないので、そのまま
モジュール直下に出せる。4 つは `templates` を引数で受ける。ルートは動かさない。

- **どこからも使われていない補助が 1 つある:** `_propose`（23 行）。4-1 で消す
- `generate_task` は #524 でルートでなくなり、`generate_without_unit` から呼ばれる補助になった

## 動かす前に厚くするテスト

テストの中の URL の文字列で数えて、参照が 1 回のルート（URL を補助関数で組み立てて
いるテストは数え漏れるので、目で確かめて除いた）。**その領域を移す PR の前に**、いまの
振る舞いを写すテストを足す。

| 領域 | ルート |
|---|---|
| A1 | `POST /manage/subjects/{name}/rename` |
| A3 | `POST …/kc/edit` |
| A4 | `POST …/units`（問題セットを開く）、`POST …/units/{unit}/completion`、`…/confidential`、`…/screen-capture` |
| A6a2 | `POST …/tasks/{task_id}/reference-solution`、`…/test-cases/propose` |
| A6c | `POST …/units/{unit}/bundle` |

課題（A6）は最後に移す（計画書の段階 4 の表）。A6 の中でも、共有の `task_page.py` を先に
出し、`tasks`・`task_data`・`task_ops`・`drafts`・`bundles` を 1 本ずつ移す。

## 測り方

- ルートの領域はパスで決めた（`/tasks/…` と `/drafts` と `/bundle` を先に判定し、
  `/units/{unit}/tasks/new` のような課題のルートが問題セットに数えられないようにした）
- 補助の帰属は、ルートの関数が参照する補助を、補助どうしの参照をたどって閉包したもの
- 行数はデコレータを含む関数の行数（`end_lineno - lineno + 1`）
