# ADR 0014: 成績の自動確定は、締切ではなく採点完了から数える

- ステータス: 採用
- 日付: 2026-08-30
- 関連: ADR 0009（判定を即時に示し、異議を受ける）/ ADR 0010（確定はレビューではない）/ ADR 0013（遅延は減点）/ 設計原則 P5

## 背景

自動確定の起点は課題の締切だった（`deadline_for(due_at, after_minutes)`）。
ADR 0009 が作った 2 段の窓は、こう動いていた。

```
採点完了 ──→ OPEN         AI の判定。確定の予定はまだ告げられない
   締切 ──→ PROVISIONAL  「MM/DD HH:MM に確定します」
締切 + n ──→ ELAPSED      確定してよい
```

これには 3 つの不都合があった。

**1. 締切前に出した学習者ほど待たされる。** 採点は提出の数秒後に終わるのに、
点が閉じるのは締切の後である。その間、学習者が「出し直すべきか」を判断する
材料は「暫定」のままで、しかも待っている理由は自分の提出とは関係がない。

**2. 締切の無い課題は確定しようがなかった。** `deadline_for` は `due_at` が
`None` なら `None` を返すので、締切を入れていない課題の成績は未確定のまま
学期末まで残った。

**3. 異議の窓が提出によって不公平だった。** 窓は締切から数えるので、締切 + n
の直前に採点された提出（＝遅れて出したもの）には数分しか残らなかった。

## 決定

**起点をその提出の採点完了時刻（`GradingRun.created_at`）にする。**

```
自動確定の設定なし ──→ OPEN         確定の予定が無い
採点完了           ──→ PROVISIONAL  「MM/DD HH:MM に確定します」
採点完了 + n       ──→ ELAPSED      確定してよい
```

`deadline_for` は `settles_at(graded_at, after_minutes)` に改めた。名前が
締切を指したままだと、起点を取り違えたまま読める。

### 早く確定させてよい理由

**確定は再提出を妨げない。** 提出を受け付けるかを決めるのは
`Task.accepts_submissions_at()` だけで、見るのは提出開始時刻である
（締切すら見ない ── 遅延は減点で表す・ADR 0013）。`Finalization` はここに
関与しない。

**採用されるのは最高得点の提出**（`aijudge_studentweb.progress`）。直して
出し直せばそちらが採られ、前の確定は影響しない。

つまり早い確定は「もう直せない」を意味しない。**むしろ締切前に確定するので、
締切前に、遅延減点なしで直せる。** 締切起点のときは、確定した時点で既に締切を
過ぎており、出し直すと減点が付いた。

**判定の理由が返ることが前提である。** 何が違うのかが分からなければ、確定が
早いことは「直せないまま閉じた」と同じである（`code_test_runner` が書式の
食い違いを名指しするのはそのため）。

## 帰結

- **締切の無い課題も自動確定の対象になる。** 採点完了は必ずあるため。
- **異議の窓が提出ごとに独立する。** 遅れて出した提出にも同じ長さの窓がある。
- `auto_finalize_after_minutes` の意味が変わる。**運用中のコースに入っている
  値は、そのまま新しい意味で解釈される** ── 「締切 + 10 分」のつもりの値は
  「採点 + 10 分」になり、確定は大幅に早まる。値の移行はしない（新しい意味の
  方が短い側に倒れるので、放置しても確定が遅れることはない）。
- 問題セット単位の「いつ確定するか」は無くなった。確定時刻は提出ごとに違う。
  教員の画面が持っていた `UnitGroup.auto_finalize_at` は削除し、「この回の
  締切を過ぎたか」（`deadline_passed`）だけを残した ── 教員が見たいのは
  「締切を過ぎたのに未確定が残っている」であり、それは依然として締切の話である。
- `FinalizationSource.DEADLINE_ELAPSED` は `AUTOMATIC` に改名した。**保存値
  `"deadline_elapsed"` は変えない** ── 確定済みの記録がその文字列で保存されて
  おり、変えると過去の成績の経緯が読めなくなる（P8）。

## 却下した案

**新しいフィールドを足し、締切起点も残す。** 設定項目が 2 つになり、教員は
どちらが効くのかを考えることになる。締切起点に残す価値のある用途が見つからな
かった（上の 3 つの不都合はどれも締切起点そのものから来ている）。

**採点直後に確定する（猶予を 0 にする）。** 異議を出す窓が無くなる。ADR 0009
が作ったのはその窓であり、告げてから閉じるという順序に意味がある。
