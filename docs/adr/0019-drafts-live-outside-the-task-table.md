# ADR 0019: 承認待ちの課題は課題表の外に置き、却下は記録しない

- ステータス: 採用
- 日付: 2026-09-15
- 関連: 設計原則 P5, P8 / ADR 0008 / #306, #319, #321

## 背景

生成した課題は、**その場で課題（`Task`）として保存し**、版を `IN_REVIEW` に
して承認を待っていた。承認の導線はその版のレビュー状態を書き換えるだけである。

この形には 2 つの帰結があった。

### 1. 承認より前に同一性が決まる

課題キーから課題 ID が決まり（`derived_id`）、提出も採点結果も監査記録も
その ID にぶら下がる。キーは変えられない ── 変えれば別の課題になる。つまり
**生成した時点で「この課題はこういう名前である」と決め切っていた。**

しかし生成物は提案であって確定ではない（P5）。**中身を読んでから名前を直したい**
というのが、承認という段の意味そのものである。教員は生成の前にキーを打たされ、
生成物を読んだあとで直す手段が無かった。

### 2. 未承認の版が「課題の状態」として読まれた

既存の課題を AI で書き直す経路（#306）を足したところ、改訂を却下すると問題
セットの一覧が「**却下済み — 出題されません**」と出た。学習者には 1 つ前の
承認済みが出ているのに、である（#319）。一覧が `latest_version` のレビュー状態
をそのまま課題の状態として出していたからだが、**そもそも未承認の版が課題の
履歴に積まれていること**が、この読み違いの土台だった。

## 決定

**承認待ちの課題は課題表の外（`task_drafts`）に置く。承認したときに初めて
課題になる。**

| | 生成の時点 | 採用（承認）の時点 |
|---|---|---|
| 新規 | 下書きができる。課題は無い | 課題と第 1 版ができる。**キーはここで確定** |
| 改訂 | 下書きができる。版は増えない | 既にある課題の新しい版になる。キーは変えない |

下書きは**版を積まない**（同じ ID に上書きする）。積むのは課題版だけで、それは
出題済みの採点基準を書き換えないための規則（P8）である ── まだ出題されていない
ものに、その規則は要らない。**採用の瞬間まで、キーも題名も問題文も出題先も
制約なく直せる。捨てるのも自由である。**

### 却下は記録しない

**却下した下書きは即時に消す。** 承認率（生成物のうち教員が承認した割合）は
測らなくなる。

設計方針 §9.2 は Phase 4 の合格基準として「教員承認率 ≥ 60%」を挙げており、
`task_review.py` はそれを数えるために却下を残す前提で書かれていた。それを
やめる理由は、**その数が何を測っているのかを説明できないから**である。

- 承認率は「生成の質」ではなく「**いまのプロンプト × この教員の好み**」を測る。
  プロンプトを 1 行変えれば動く数を、単一の合格基準に据える意味が無い。
- 採点者は事実上 1 人で、`MIN_SAMPLE_SIZE = 30` に達するまで `NOT_MEASURED`
  であり続ける。その間、基準は「まだ測れていない」以上のことを言わない。
- 却下を残す義務は、「未承認の下書きは制約なく消せる」という上の決定と
  正面からぶつかる。

**プロンプト版ごとに比べる**用途（版 1 → 版 2 で承認率が上がったか）は否定
しない。それは作問を改善したい時にその都度行う実験であって、常時掲げておく
指標ではない ── 採点の一致度を `evals/report_ja/` で測るのと同じ位置づけである。

## 帰結

- `approval_rate` は `NOT_MEASURED`（理由: 却下を記録していない）を返す。
  **承認だけを数えて 100% と出すことはしない** ── 正当化できない数値を報告
  しないのは、この設計全体の約束である。
- 設計方針 §9.2 の表から「教員承認率 ≥ 60%」を外し、測らないと決めた旨を書く。
- 未承認の版という状態が無くなるので、#319 の読み違い（未承認・却下を課題の
  状態として出す）は土台から消える。`ReviewState` は残る ── 束の取り込みが
  使っており（#161）、承認済みかどうかは課題版の性質として要る。
- **移行前の承認待ちは引き継がない**（2026-09-15 決定）。`task_drafts` は空で
  始まり、`task_versions` に残る `IN_REVIEW` の行は一覧に出なくなる。運用機に
  残っている待ちは、課題の画面から削除して入れ直す。
