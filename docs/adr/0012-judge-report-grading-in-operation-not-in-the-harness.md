# ADR 0012: レポート採点の合否は実運用の blind 採点で判定し、測定用ハーネスを本番に入れない

- ステータス: 採用
- 日付: 2026-08-29
- 関連: 設計方針 §9.2 Phase 3, §11 / 設計原則 P3, P5, P7 / ADR 0002, ADR 0005, ADR 0007

## 背景

設計方針 §9.2 Phase 3 は 2 つの合格基準を課している。

1. `packages/core` と `packages/grading` への変更行数が 50 行未満
2. 教員採点との一致度 QWK ≥ 0.60

**1 は満たした。** レポート科目を足すのに変えたのは `subjects/report_ja.yaml` と
プラグイン 3 つ（`document_text` / `report_structure` / `submission_compliance`）だけで、
コアと採点エンジンの差分は 0 行。`import-linter` の 15 契約も無傷である。
Phase 3 の仮説（新しい科目種の追加が YAML とプラグインだけで済む）は成立した。

**2 は、いまのやり方では判定できない。** 手元にある照合先は 2 つしかない。

| データ | n | 照合先 | 最良の合計 QWK |
|---|--:|---|--:|
| 2025 年度 | 19 | LLM が付けた採点表 | 0.397（`2025d`） |
| 2023 年度 | 28 | 教員本人の採点 | 0.530（`qwen3.8`） |

どちらも `evals/gates.yaml` の `min_sample_size: 30` を下回るので、**形式的には
どちらも `NOT_MEASURED`** である。数字の側にも 3 つの限定がある。

- **段階の記述はこちらが書いたものである。** 教員のルーブリック文書は残って
  おらず、採点表にあるのは観点名と配点だけ。測れているのは「教員のルーブリック
  に対する精度」ではなく「こちらが書いた記述に対する精度」でしかない。
- **記述を変えると順位が変わる。** 同じモデル・同じ提出でも、ルーブリックの
  記述を変えただけで合計 QWK は 0.234〜0.599 の幅で動いた。**モデル選択より
  記述の影響の方が大きい。**
- **照合先を変えるとモデルの順位が反転する。** 2025 年度（LLM の採点表）で
  最良の `gemma4` は、2023 年度（教員本人）で最下位になる。**LLM が付けた
  採点表を物差しにしてモデルを選ぶと、教員に対して最も悪いモデルを選びうる。**

ハーネスの中で記述を書き直しては測り直す作業は、続けても
「こちらが書いた記述の当たり外れ」を測り続けるだけで、収束先が無い。

## 決定

### 1. Phase 3 の 2 番目の基準は、実運用で貯めた `BlindMark` に対して判定する

`subjects/report_ja.yaml` の `measurement.blind_sample_rate: 0.2` が抽出する、
**教員が AI の判定を見る前に付けた段階**（ADR 0005）を照合先にする。1 観点
あたり 30 件が貯まるまで、Phase 3 の一致度は `NOT_MEASURED` のままとする。

これは基準を緩めるのではなく、**判定の場所を変える**決定である。数値
（QWK ≥ 0.60）は動かさない。`evals/gates.yaml` も書き換えない。

**運用の開始はこの判定を待たない**（ADR 0007）。レポート採点には即時性の
要求が無く（§9.1 の p95 < 30 秒は決定的評価だけを対象にしている）、AI の
判定は提案でしかなく、確定は教員が持つ（P5）。**判定できないことは、
使えないことではない。**

### 2. モデル選択も同じ場所で行う

どのモデルを既定にするかは、実運用の `BlindMark` に対して測ってから決める。
ハーネスの数字（現状 `gemma4` / `qwen3.8` のどちらが良いかが年度で反転する）
を根拠にモデルを固定しない。

### 3. 測定用ハーネスのコードは本番に入れない

`evals/report_ja/` は使い捨ての道具として `evals/` の下に留める。そこで得た
知見は **科目プロファイルと評価器に書き写して**移し、コードは移さない。
入れると 2 つ壊れる。

- **ADR 0007 が壊れる。** ハーネスは教員の採点表（生の点数）を読む。本番の
  採点経路がそれを読めるようになった時点で、「照合先を見ながら採点する」
  経路が存在してしまう。
- **P7 の境界が壊れる。** ハーネスは氏名と学籍番号を含むデータを前提に
  書いてある。本番から参照できる位置に置くと、個人情報の境界が設計から消える。

機械で保証する手段を `tests/test_evals_stay_out_of_production.py` に置く。
`import-linter` では守れない ── ハーネスは配布物件ではなく `sys.path` を
書き換えて動く素のスクリプトの集まりで、契約が参照できるモジュール名を
持たないからである。だから本文を読んで、本番系（`packages` / `evaluators` /
`normalizers` / `apps`）に `evals` への参照が無いこと、ハーネスが workspace
member にも依存にもなっていないこと、学生データの置き場が `.gitignore` に
載っていることを検査する。

## 帰結

**知見のうち、この決定にともなって本番へ写したもの。**

| 移したもの | 根拠 | 移し先 |
|---|---|---|
| 体裁は本文ではなく提出そのものを見る | 教員採点との完全一致 42.9% → **71.4%** | `deterministic: [submission_compliance]` |
| 自己一貫性のサンプルは 3 本 | 2 本では確信度が 1.0 か 0.5 の二値にしかならず、レビュー行き 37〜58% | `rubric_ai_judge.samples: 3` |
| 確信度の閾値は 0.6 | 3 本での 2 対 1（0.67）を通し、3 つに割れた場合を通さない | `review_policy.confidence_below` |

**遅延は評価器に入れない。** `submission_compliance` は提出の有無と形式だけを
見る。71.4% という数字も**遅延を見ない規則**の値である（ハーネスは締切を
渡していない ── 渡す口が無く、評価用のデータにも締切が入っていない）。
内訳は「28 件中 20 件が体裁で満点」で、規則の中身ではなく
**満点を既定にしたこと**が効いている。

残る 8 件（半分が 6 件・最低が 2 件）が教員の付けた事務的な減点で、
採点表の備考は `遅延14h` と `ファイル名` である。**これを観点の段階として
表現しない。** 評価は遅延と独立に行い、遅延は評価の結果に対する減点として
別に持つ ── 混ぜると観点の κ が「読解」と「事務」の混合を測ることになる。
実装は別 ADR で扱う。

**残る限定。** 実運用の `BlindMark` で測っても、判定できるのは
「このルーブリック記述とこのモデルの組合せ」の精度である。記述そのものの
良し悪しは、記述を書いた人間の責任として残る。**「レポートは AI に採点できる／
できない」という一般の結論は、この経路からは出ない。**

## 却下した案

**ハーネスで記述を書き直し続けて 0.60 に届かせる。** 届かせられるとしても、
届いた先にあるのは「28 件に当てはめた記述」である。標本が 30 件に満たない
うえ、当てはめた標本で測り直せば必ず良くなる。過学習を測っているのと
区別できない。

**Phase 3 を「不合格」として止める。** 止める理由が無い。アーキテクチャの
仮説（Phase 3 の本丸）は成立しており、一致度は ADR 0007 で採点運用から
切り離されている。止めれば、判定に必要な `BlindMark` を貯める場所も失う。

**基準を 0.60 から下げる。** `evals/gates.yaml` は「緩めるのは、緩める理由を
ADR に書いてから」と要求している。**いま持っているのは「届かない」ではなく
「測れていない」**なので、下げる理由が無い。
