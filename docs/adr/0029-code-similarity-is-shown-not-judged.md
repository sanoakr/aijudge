# ADR 0029: 提出どうしの類似は示すだけで判定しない。Dolos を sandbox で動かし、DB に書かない

- ステータス: 採用（2026-09-29。実装は issue #203）
- 日付: 2026-09-29
- 関連: 設計原則 P2, P5, P7, P8 / ADR 0004, 0006, 0016, 0020, 0023, 0027, 0028

## 背景

同じ課題の提出どうしで酷似する組を教員に示したい。行動記録（ADR 0023）と試験中の
静止画（ADR 0027）は「一人の提出がどう書かれたか」を見るもので、「誰と誰が似ているか」
は見えない。

道具には Dolos（ゲント大学・MIT）を使う。tree-sitter で構文を抽象化するので、
変数名を変えただけの写しも見つかる。Node/TypeScript 製で、Python から直接は呼べない。

当初（2026-09 初め）は「Dolos のサーバを自前で立て、ゲートウェイ経由で HTTP で話す」
（ADR 0004 の形）を考えた。自前運用の文書を読み直すと、**Dolos のサーバは検査ごとに
コンテナを起動するため docker.sock をマウントする**。ホストの root を渡すのと同じで、
提出物を gVisor で動かしている運用機（`AIJUDGE_SANDBOX_MIN=kernel_isolated`）の横に
置けない。

## 決定

### 1. 判定しない。組を担当教員に示すだけ（P5）

同じ課題を解けば似る。入門課題は正解がほぼ 1 つしかない。出すのは組・類似度・
該当箇所で、**「盗用」という語を自前の画面で使わない**（Dolos の画面は自ら
「plagiarism detection」と名乗る。配布物は書き換えない）。

- **成績にはつながない。** 成績を作る処理（採点ワーカー・採点エンジン・確定）は検査の
  モジュールを import できない（`.importlinter` の `grades-do-not-read-similarity`）
- **見るのは担当教員だけ。** TA は見ない。学習者には出さない。閲覧は監査ログに残す
  （ADR 0016・0027 と同じ扱い）

### 2. Dolos の CLI を、提出物と同じ sandbox で 1 回ずつ動かす（P7）

- イメージは **digest で固定**した `ghcr.io/dodona-edu/dolos-cli`（v2.9.3）。
  運用者が `AIJUDGE_SANDBOX_IMAGES` で許可したものしか動かない（#419 と同じ関門）
- sandbox はコンテナに限る（`build_tool_sandbox`）。seatbelt や隔離なしへは落ちない。
  ネットワークなし・読み取り専用・nobody・gVisor
- サーバは立てない。常駐するものも docker.sock を持つものも増えない
- ホストされた dolos.ugent.be へ送る経路はコードに存在しない。ネットワークが無いので、
  設定を誤っても構造的に外へ出られない

運用機（gVisor）で実測した制限: プロセス数 64・メモリ 512 MiB が要る（32 では分析が
落ち、24 以下ではコンテナが立たない。runc では 16 でも動いた ── 手元の結果を根拠に
しない）。時間は件数の 2 乗に近い（C 60 件 6 秒・300 件 102 秒）ので、**課題ごとに**回す。

### 3. DB に書かない。報告と `run.json` をファイルで残す

回ごとに `AIJUDGE_SIMILARITY_DIR/<コース>/<課題>/<回>/` に Dolos の CSV（`data/`）と
`run.json` を置く。`run.json` にはイメージ・引数・入力のハッシュ・件数・仮の名前と
提出の対応・測れなかった理由を入れる（P8 の再現性）。入口のページ・自動実行・後始末は
これだけを読む。

ADR 0028 は「複数のサブシステムにまたがる処理は業務の層に書く」とした。検査は提出を
読み、成果物を読み、sandbox で動かす ── 業務の層（`aijudge_course_admin.code_similarity`）の
操作である。表を足さないので、migration も保存層の 2 実装も要らない。

### 4. 報告は提出の写しとして扱う

報告の `files.csv` には全員のコード全文が入る（入力の約 40 倍の大きさ）。

- **課題ごとに最新の 1 回だけ**残す
- **提出と一緒に消す。** 入れた提出のどれかが消えたら（削除・purge・コースの削除）、
  報告を丸ごと消す
- **バックアップしない**（動画・静止画と同じ・ADR 0020）
- 画面に出る名前は仮のもの（`S-001`）。実名・学籍番号・提出 ID を Dolos に渡さない

### 5. 測れなかったら `NOT_MEASURED` と理由を残す

件数が 2 未満・上限（300 件）超え・C と Python 以外・言語の混在・sandbox が使えない・
道具の失敗。「似た組が 0」と区別する。環境の不調（sandbox・道具の失敗）だけは、入力が
同じでも次の周回で回し直す。

### 6. 比べ方は 2 つ。コードとして、テキストとして（#569・2026-10-28 追記）

課題ごとに 2 回回し、入口のページで切り替える（`?mode=code|text`）。

- **コードとして**: いままでの検査。識別子を抽象化して構造で比べ、コメントは読まない。
  C・Python のコードの提出だけ
- **テキストとして**: 提出をそのまま文字で比べる（Dolos の `char`）。コメント・説明文の
  写しはこちらでしか見えない。コード（言語を問わない）・Markdown・LaTeX の提出。
  比べる長さは `-k 10 -w 5`（既定の 23 文字は日本語に長い）で、**値は仮**。`run.json` の
  `params` に残す

**Dolos の `-C`（コメントを含める）は使わない。** コメントを「ここにコメントがある」という
1 つの印として数えるだけで、中身を比べない。手元で、同じ説明文を写した組とまったく違う
説明文の組を比べ、どちらも類似度が変わらないことを確かめた。コメントだけを抜き出して
比べる案も捨てた ── どのコードの行への説明かが分からなくなる。

**文字の一致は言い換えを見つけない**（同じ内容を言い換えた組は 0）。言い換えまで見るのは
別の比べ方（埋め込み）で、Dolos の外になる（別に決める）。

入口のページの組の表には、**同じ組のもう一方の類似度も並べる**。コードは違うのにテキストが
高い組（説明文の写し）と、コードが同じでテキストが下がる組（コメントの書き換え）は、片方
だけでは見えない。突き合わせは仮の名前ではなく提出で行う。仮の名前は学習者 1 人 1 件の並びで
振るので、2 つの比べ方で同じ人は同じ名前になる。回は比べ方ごとに最新の 1 回だけ残す
（テキストの回の名前は `-text` で終わる）。`mode` の無い `run.json` はコードとして読む。

### 7. 3 つ目の比べ方は内容として。埋め込みで、段落ごとに（#569・2026-10-28 追記）

Dolos は言い換えを見つけない。レポートでは同じ内容を別の言葉で書いた組を見たいので、
**手元のモデルの埋め込み**で段落ごとの意味の近さを測る（`aijudge_course_admin.content_similarity`）。

- 対象は Markdown・LaTeX・PDF・docx（PDF・docx は採点と同じ `document_text` で本文にする）。
  **コードは入れない** ── コードの言い換えはコードとしての比較が拾う
- 組の値は「互いの段落が、相手のどれかとどれだけ近いかの平均」（両側の平均）。1 段落だけ
  同じ組と、全体を言い換えた組を分けるため、最も近い 1 組ではなく平均を取る
- 根拠は、互いに最も近く、しきい値（仮に 0.75）を超えた段落の組。Dolos の画面は無いので、
  入口のページに段落を並べる（`data/passages.json`）
- **同じ課題のレポートは写していなくても近い。** 課題ごとの組の中央値を `run.json` の
  `baseline` に残し、画面はそれと並べて示す
- **学習者の文は `DataClass.PERSONAL` で `LlmGateway` を通す**（P7）。経路は採点と同じ主系
  （PAIR）と従系（slab-llm）で、**どちらにも同じモデルを入れる**。違うモデルの値は比べ
  られないので、モデルは `run.json` の `image`（`embedding:<model>`）に残し、替われば測り直す
- モデルは `AIJUDGE_SIMILARITY_EMBEDDING_MODEL`。**未設定なら内容としては比べない**

モデルは qwen3-embedding:4b（2026-10-28 決定）。手元で作った日本語 6 組で、同じ課題で独立に
書いた段落と言い換えを 1 つのしきい値で分けられたのは、比べた 9 つのうち qwen3-embedding の
4b と 8b だけだった（8b は時間が 2 倍で、利点が無い）。しきい値と段落の分け方は、実際の
レポートの提出が集まってから決め直す。

**図表はこの比べ方に統合する**（レポート内の図表を前提とするため）。いまは本文として取り出せる
文字（表のセル・軸の名前・図の題）だけが入る。図そのもの（画像の知覚ハッシュ・ベクター図の
折れ線）は、実際の PDF で測ってから足す。

### 8. 指定した相手（他の課題・過年度の束）とも比べる（#653・2026-10-28 追記）

過年度のレポートを写して出していないかを見るため、課題ごとに比べる相手を指定できるようにした
（`Task.similarity_references`。`course.yaml` の課題に書く）。

- **相手は課題ごとに指定する。** 自動で広く比べると、関係のない課題と比べて空振りが増えるだけ
- 他の課題は `{course, term, task}`（省けばこのコース）。ID は導出で決まるので
  （`course_id_for`）、まだ無いコースを書いても壊れない。コースを複製すると、このコースを
  指していた相手は**元のコースに固定する**（写した先の自分と比べないため）
- 過年度のレポートは aiJudge の外にある（運用は 2026 後期から）。年度ごとの PDF の束を
  `aijudge-admin similarity archive import` で取り込む。**取り出した本文だけを置き、PDF も
  元のファイル名も置かない**（ファイル名に学籍番号が入っていることが多い。運用者の確認用に
  manifest にだけ残し、画面と CLI の要約には出さない）
- 比べるのは**この課題の提出 × 相手**だけ（テキストとして・内容として）。相手どうし・提出
  どうしの組は捨てる。束の埋め込みはモデルごとに保存して使い回す
- **相手の側は出どころ（ラベル）と類似度しか出さない。** 相手の名前も本文も出さない
  （2026-10-28 の決定）。Dolos の報告は `pairs.csv` だけを持ち出し（`files.csv` には相手の
  本文が入る）、Dolos の画面は開かない
- 束は提出の報告と同じ扱い: バックアップしない、コマンドで消す。消すと、比べた報告も次の
  周回で消える（`sweep_orphans`）

## 却下した案

**Dolos のサーバを自前で立てる**（当初案）。docker.sock を渡すことになる。常駐する
Web サーバ・API・MariaDB が増える。10 MB の上限・ポーリング・報告の `DELETE` を
こちらで持つ必要もある。

**ホストされた dolos.ugent.be を使う。** 学習者全員の提出を zip で他大学のサーバへ
送ることになる（P7 に反する）。

**自前の比較画面を作る。** 該当箇所は `pairs.csv` に無く、Dolos の画面がブラウザで
`kgrams.csv` から計算している。作り直しになる。Dolos の画面（静的ファイル）を
コンソールが配れば足りる。

**結果を DB の表に持つ。** 入口のページに要るのは `run.json` で足りる。表を足すと、
報告（ファイル）と行の食い違いを扱う必要が生まれる。
