# ADR 0023: 行動記録は 4 つ目の記録であり、何も止めない

- ステータス: 採用（2026-09-24。手元での 150 名の負荷試験のあと、v1.18.0 で main に入れた）
- 日付: 2026-09-24
- 関連: 設計原則 P2, P5, P7, P8 / ADR 0016, 0019, 0020 / 設計方針 §2.2 の S10 /
  `docs/design/online-coding-test.md` §6・§7

## 背景

オンラインコーディングテスト（ブラウザ IDE）では、学習者がコードを**どう書いたか**
── 打鍵・貼り付け・コピー・ファイル読み込み・実行・ウィンドウを離れた時間 ── を
時刻付きで残したい。生成 AI や他の学習者からの貼り付けを**推定する材料**にする
ためである。

ADR 0016 は「新しい記録を足すときは、表のどの行かを言えなければ置き場所が
決まらない」と定めた。この記録は既存の 3 つのどれにも当たらない。

- **運用ログではない。** 学習者のコードそのものを含む。journald に流せば、
  学習者データを暗号化もバックアップの管理も無い場所へ複製することになる（P7。
  `aijudge_telemetry.bind` が本文を弾くのと同じ理由）
- **監査ログではない。** 量が桁違いで（90 分・150 名で約 8 万バッチ）、
  `detail` の 4000 字にも収まらない。そして監査の性質 ──「書けなければ操作ごと
  失敗させる」── をここに持ち込むと、**記録の不調で試験が止まる**
- **採点記録ではない。** 成績の根拠にはしない（§4 の決定）

## 決定

### 1. ADR 0016 の表に 4 行目を足す

| | 何の記録か | 置き場 | 消えてよいか | 書けなかったら |
|---|---|---|---|---|
| 運用ログ | プロセスに何が起きたか | journald | よい | 何もしない |
| 監査ログ | 誰が成績に関わる何をしたか | `audit_events` | だめ | 操作ごと失敗 |
| 採点記録 | どの版・どのモデルで採点したか | `GradingRun` | だめ | 採点を保存しない |
| **行動記録** | **学習者がコードをどう書いたか** | 本体はファイル、索引は DB | **保存期間を過ぎたら消す** | **何も止めない。欠落として残す** |

### 2. 書けなくても、編集・実行・提出は止めない（P2）

行動記録の受け口が落ちても、ストレージが一杯でも、IDE の編集・自動保存・実行・
提出はそのまま動く。記録が欠けた区間は、**欠けたこと自体を事実として残す**
（バッチの `seq` の飛び、ハートビートの途切れ）。

欠落は不正の証拠として扱わない。通信の不調と区別できないからである。
混雑時にサーバは `503 + Retry-After` を返して送信間隔を広げさせる ── 記録の
欠けより、IDE が重くなるほうが試験を壊す。

### 3. 本体はファイル、索引は DB

- 本体（イベント列とコード全文のスナップショット）は動画と同じストレージ
  （`AIJUDGE_ACTIVITY_DIR`、既定は `/work/aijudge/activity/`）に置く
- DB には索引（`ide_sessions`・`ide_event_batches`）だけを置く。バッチには
  `(ide_session_id, seq)` の一意制約を掛け、再送を重複させない
- 書く順は**ファイル → DB**。一時ファイルに書いて `rename` するので、途中で
  落ちても残るのは孤立したファイルだけで、半端な索引は残らない
- **イベント 1 件を 1 行にしない。** 打鍵単位だと 1 試験で数百万行になる

自動保存（`ide_buffers`）はこの記録に含めない。締切時の自動提出が読む、採点の
入口に近いものなので DB に置き、行動記録とは別の表にする。ADR 0019 の
`task_drafts` と取り違えないよう、名前に `draft` は使わない。

### 4. 成績には一切つながない（P5）

行動記録から出すのは教員向けの**フラグと再生**だけで、自動で減点しない。
誤検知の不利益が、見逃しの不利益より大きすぎる。

`aijudge_grading` と `evaluators/*` は `aijudge_ide` を import しない
（`grading-does-not-know-ide` 契約）。フラグの計算を足す段階（段階 4）では、
フラグが成績に届かないことを import 契約とテストで固定する。

### 5. 保存期間・閲覧・告知

- 保存期間は動画と同じ（ADR 0020）。締切のある課題は締切から 6 か月、無い課題は
  セッションの開始から 1 年。purge は `aijudge-admin` で、既定は下見
- 閲覧はそのコースの教員だけ。**閲覧したことを監査ログに残す**
  （`AuditAction.ACTIVITY_VIEWED`）。学習者本人のデータなので、誰がいつ見たかを
  後から説明できなければならない
- IDE を初めて開いたとき、何を記録し、何に使い、何に使わないか（自動で減点しない）を
  示し、確認を取ってから始める。確認したことも記録する

## やらないこと

- **画面・カメラの録画。** ブラウザからは他のアプリの画面が見えず、得られるものに
  比べて負担と個人情報の重さが釣り合わない。コード全文のスナップショットで代える
- **貼り付け・ウィンドウ移動の禁止。** ブラウザでは強制できない。強制したふりを
  すると、記録の信頼性だけが下がる
- **受信時の解析。** 受け口は認証の解決と 1 INSERT だけにする

## 帰結

- 行動記録は**クライアントが送ってくるもの**であり、開発者ツールで止めることも
  偽ることもできる。「記録がある」ことは材料になるが、「記録が無い」ことは潔白の
  証明にならない。欠落・再構成の不一致・提出内容とエディタ状態の不一致は、
  判断を加えずに事実として教員に示す
- 行動記録を止めても試験は進む。監査ログを止めると成績は変えられない。この非対称は
  ADR 0016 の非対称と同じく意図したものである
- restic の保持期間と保存期間の整合（ADR 0020 で未了）は、行動記録にもそのまま
  当てはまる。動画側で決めたものに揃える
