# ADR 0015: 「機械が採点しなかった観点」を理由ごとに分けて持つ

- ステータス: 採用
- 日付: 2026-08-31
- 関連: 設計原則 P5, P8 / ADR 0005, ADR 0007, ADR 0010 / Issue #10（#5・#7 の前提）

## 背景

観点に `CriterionScore` が無い状態を、`GradingRun.unscored_criteria` という
**1 つのリスト**が表していた。そこから 4 つの帰結がまとめて付いてくる。

1. `renormalize()` が残りの観点の重みを 1.0 まで比例配分する
2. `Routing.REVIEW_REQUIRED` になる（`_check_unscored` が強制）
3. 学習者には総合点を出さない（`visibility.build_result_view` の `withhold`）
4. 自動確定の対象外になる（`auto_finalizable` が `is_provisional` で弾く）

この 4 つは**「評価器が落ちた」というただ 1 つの状況のために設計されたもの**で、
ADR 0007 の「部分的な総合点は、完全な総合点に見えるので出さない」が根拠である。

ところが、これから作る 2 つの機能はどちらも「機械が点を付けなかった観点」を
新しく作り、しかも**その状態に正反対の振る舞いを求める。**

- **AND ゲート**（#5）── 上位の観点が 0% になったら以降を打ち切り、
  **未評価のまま 0%** とする。これは保留ではなく確定した 0 点である
- **人が採点する観点**（#7）── 評価器を割り当てない観点。人が入れるまで
  閉じてはいけない

同じバケツに入れると、片方が必ず壊れる。とくに 1 の重み再配分は**点そのものを
間違える。** 観点 4 つ（重み 0.3 / 0.3 / 0.2 / 0.2）で 2 つめが 0% になり、
3・4 を打ち切った場合:

| | 意図（#5） | 再配分した場合 |
|---|---|---|
| c1 (1.0) | 0.3 | 重み 0.5 に膨らむ → 0.5 |
| c2 (0.0) | 0.0 | 重み 0.5 に膨らむ → 0.0 |
| c3 c4 (打ち切り) | 0.0 | 計算に入らない |
| **合計** | **30%** | **50%** |

**打ち切られた学習者の点が上がり、AND の意味が消える。** 逆向きの誤りも同じ
場所から出る ── 人採点の観点をゲートと同じに扱えば、誰も見ないまま成績が閉じる。

## 決定

`GradingRun` が、機械の判定が無い理由を**別々のリストとして**持つ。

```python
unscored_criteria: tuple[CriterionId, ...]   # 評価器が落ちた（既存の意味のまま）
skipped_criteria:  tuple[CriterionId, ...]   # ゲートで打ち切った（#5）
awaiting_human:    tuple[CriterionId, ...]   # 人が採点する（#7）
```

帰結は理由ごとに決める。

| 状態 | 重み再配分 | 総合点 | レビュー必須 | 自動確定 |
|---|---|---|---|---|
| 評価器が落ちた（既存） | する | 保留 | する | 止める |
| ゲートで打ち切った | しない（0% として重みどおり計上） | 出す | しない | 止めない |
| 人が採点する | しない（人の入力を待つ） | 保留 | する | 止める |

実装上の要点は 3 つ。

- **`is_provisional` は「点が定まっていないか」を意味する。**
  `unscored_criteria or awaiting_human` であって、ゲートの打ち切りを含まない。
  自動確定も学習者への総合点の保留も、判定の有無ではなくこの値で決める
- **`renormalize()` を使ってよいのは `unscored_criteria` に対してだけ。**
  0% として数える観点は `aggregate(..., zero_weight=...)` に重みを渡す。
  渡し忘れれば重みの合計が 1.0 に届かず、`aggregate` が落とす ──
  **黙って比例配分し直す経路を残さない**
- **1 つの観点に理由は 1 つだけ。** 点が付いている観点をどれかのリストに
  入れることもできない。どちらもコアの検証で落とす

## 検討した別案

**1 つのリストに理由を添える**（`unscored: tuple[tuple[CriterionId, Reason], ...]`）。
読む側が毎回 `Reason` で分岐することになり、**分岐を忘れた場所が静かに従来どおり
動く** ── まさにこの ADR が塞ごうとしている壊れ方と同じ形なので採らない。
分けておけば、新しい状態を読み落とした場所は型と検証で見つかる。

## 帰結

- 既存の記録はそのまま読める。新しい 2 つの既定は空で、当時は「評価器が落ちた」
  しか存在しなかったので意味も変わらない（追記のみ、P8）。`GradingRun` は
  `grading_runs.document`（JSON）に入るので列の追加も要らない
- 「機械の判定が無い」ことだけを見たい側 ── 一致度の測定（比べる相手の判定が
  無いので標本に入れない）や画面 ── は `missing_criteria` を読む。
  **帰結を決める場所は理由の側を読む**
- ADR 0007 の判断は変えていない。評価器が落ちた場合の挙動は 4 つとも従来どおり
