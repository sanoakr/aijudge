# ADR 0005: 「測れていない」を「合格」に丸めない

- ステータス: 採用
- 日付: 2026-08-27
- 関連: 設計原則 P5, P8／設計方針 §09 PoC-1

## 背景

PoC-1 の合格基準は数値で書いてある。

- 教員採点との一致度 Cohen's κ ≥ 0.65
- 見逃し（自動確定したが教員の修正が必要だった率）≤ 5%
- レビュー行き率 ≤ 30%
- 同一提出を繰り返し採点したときの標準偏差 ≤ 満点の 5%

これを人手で集計すると、次の失敗が起きる。

1. **κ の実装を間違える。** 偶然一致の割引を忘れると、完全一致率 0.5 を
   κ = 0.5 と誤読する（正しくは 0 付近）。
2. **標本が少ないまま合格と判断する。** 3 件で κ = 1.0 は何も意味しないが、
   表に「1.00」と出れば合格に見える。
3. **正解データが AI に汚染される。** AI の出力を見てから教員が採点すると、
   その採点は AI に引きずられ、一致度が実力より高く出る。
4. **失敗した項目が消える。** 採点できなかった提出を集計から落とすと、
   都合の良い部分集合だけで κ を測ることになる。

この 4 つはどれも「合格していないのに合格と表示する」方向に効く。

## 決定

### 判定は 3 値にする

`PASS` / `FAIL` / `NOT_MEASURED`。優先順位は **FAIL > NOT_MEASURED > PASS**。
`min_sample_size`（既定 30）を下回る観点は、数値が何であれ `NOT_MEASURED`。

CLI の終了コードも 3 種類にする。

| コード | 意味 | CI の扱い |
|---|---|---|
| 0 | 合格 | 通す |
| 1 | 不合格 | **落とす** |
| 2 | 測定できない | 落とさないが、合格とも言わない（warning） |

2 を 0 に丸めた瞬間、この ADR の目的は失われる。

### 指標は S9 の純関数として実装し、手計算で検算する

`packages/analytics` に置き、採点の実装にも I/O にも依存させない。
Cohen's κ・QWK は手計算できる例を期待値としてテストに固定した
（κ = 0.40 の 2×2 例、QWK = 0.75 の 3 段階 6 件）。
実装が壊れれば、合格を出す前にテストが落ちる。

順序尺度には QWK も併記する。κ は「0 と 3 の食い違い」と
「0 と 1 の食い違い」を同じに扱うため、採点段階の評価には向かない。
PoC-1 の基準が κ で書かれているので両方出す。

### 正解データはリポジトリに置かない

学習者の提出と教員の採点は個人情報で、git に入れたら取り消せない。
既定の読み先はリポジトリ外（`~/.aijudge/golden`、`AIJUDGE_GOLDEN_DIR` で変更）。
`evals/golden/` に置いてあるのは形式の例（合成データ）だけで、
意図的に基準を満たさない大きさにしてある。

### blind な採点だけを正解データとして数える

各採点に `blind` を持たせ、既定では blind でないものを除外する。
AI の判定を見てから付けた採点は正解ではない。`--include-non-blind` は
差を観察するためのもので、標本を水増しするために使わない。

### 集計から黙って落とさない

- 提出が見つからない・課題定義が無いといった構成の壊れは**例外**にする。
  黙って飛ばすと、標本が減ったことに気づかないまま κ を見ることになる。
- 評価器が失敗した観点は `unscored_criteria` に記録され、標本に入らない。
  「一致した」とも「外した」とも数えない。
- 採点に失敗した項目はレポートの「失敗した項目」に列挙する。

## 帰結

- 現時点の判定は `NOT_MEASURED` である。実機で完全一致・ばらつきゼロが
  出ても、標本が 1 件なので合格ではない。**PoC-1 はまだ通っていない。**
- 合格させるには教員採点データが要る。1 観点あたり 30 件以上、blind で。
- `evals/gates.yaml` を緩めるときは理由を ADR に書く。
  「今の実装だと届かないから下げる」は基準ではない。
- 測定は `apps/evalrunner`（合成の中心）が担い、複数のサブシステムに依存する。
  サブシステムどうしは互いを import しない規則は保たれる（ADR 0001）。

## 却下した案

**合格・不合格の 2 値にする。** データが無いときに一方へ丸めるしかない。
不合格に丸めると、まだ測っていないだけの段階で赤が出続けて意味を失う。
合格に丸めるのは論外。

**pandas / scikit-learn を使う。** κ と QWK は数十行で書ける。
検算できる実装を自前で持つ方が、依存を足して中身を確かめないより安全。
