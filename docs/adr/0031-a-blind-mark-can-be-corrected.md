# ADR 0031: blind 採点は訂正できる。元の値は残し、測定は訂正の件数を報告する

- ステータス: 採用（2026-10-01）
- 日付: 2026-10-01
- 関連: 設計原則 P5, P8 / ADR 0005, 0010, 0030

## 背景

blind 採点（ADR 0005）は一度しか保存できない。AI を見たあとの段階で上書きできると、
AI に引きずられた値が正解データになるからである。

運用を始めると、**人の押し間違いが起きる**。しかも、気づくのは確定の画面で AI の判定と
食い違ったときである（2026-10-01、network の認定証で「一部（50%）」のつもりが「達成」）。
直す経路が無いので、運用機の DB を直接書き換えて直した（監査に残らない）。

## 決定

### 1. 訂正を追記する。元の blind 採点は書き換えない

`BlindMarkCorrection`（表 `blind_mark_corrections`）に、訂正後の全観点の段階・直す前の
段階・理由・誰がいつ直したかを残す。最新の訂正が効く（`corrected_mark`）。`blind_marks`
の行には触らない（P8）。

訂正は確定の画面（`reveal`）の「blind 採点を訂正する」から行う。理由は必須
（10 文字以上）、段階が変わらない訂正は断る。監査には観点ごとの前後を残す
（`blind_mark.corrected`）。

### 2. 測定には訂正後の段階を使い、訂正した件数を報告する

訂正は**必ず AI を見たあと**に起きるので、AI に近づく方向に偏る。押し間違いを直すのは
正しいが、AI を見て考えが変わっただけのものまで「訂正」されると一致度が高く出る。

- 正解データには訂正後の段階を使う（押し間違いを測定に残さない）
- 観測に `blind_corrected` を残し、測定の報告に「うち blind 採点を訂正 N 件」を並べる
  ── 偏りを消すのではなく、読む人が確かめられるようにする
- 画面では「AI を見て考えが変わった場合は訂正ではない（成績は確定の欄で直す）」と書く

訂正したものを測定から外す案は採らなかった。押し間違いが残ったままの標本と、AI に
寄った標本のどちらを避けるかの選択で、押し間違いは本人が分かっている事実である。

### 3. 直せるのは採点した本人と担当教員

押し間違いは本人がいちばんよく分かる。TA が付けた blind 採点は教員も直せる。ほかの
TA は直せない。

### 4. 訂正して AI と一致すれば、確認まで済ませる

blind の保存で一致したとき（ADR 0030）と同じ扱いにする。教員の確認がまだ無く、ほかに
人が決めることが無ければ、確認を記録して確定する（確定済みなら確認だけ足す）。
監査の経路は `via: blind_correction_agreement`。

## 結果

- 押し間違いを画面から直せる。DB を直接書き換えない
- 元の blind 採点と訂正の履歴が両方残り、測定の報告に訂正の件数が出る
- 確定の画面の成績の段階とは別の操作である（こちらは測定の正解データの訂正）
